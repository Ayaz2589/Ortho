# 9.3 Ledger integrity — atomic split persistence

> **✅ SHIPPED — spec 027 (`specs/027-ledger-atomic-persistence/`, PR #26, 2026-07-18).**
> `upsert_transaction(p_tx jsonb, p_shares jsonb)` RPC (migration
> `supabase/migrations/20260718120002_upsert_transaction_atomic.sql`) writes the
> transaction + its shares in one database transaction, with a DB-level guarantee
> that `sum(shares) = amount_cents`; execute is revoked from public and granted
> to `authenticated`/`service_role` only. Both write paths converted to the RPC:
> the web app (`web/lib/store.tsx`) and the import CLI
> (`web/scripts/import/db/persist.ts`) — closing the reachable share-less-row
> path. The migration counts pre-existing share-less rows (a `NOTICE`) but does
> not modify them. Every "How it works" bullet below was delivered;
> multi-currency stayed out of scope (see §9.5).

- **Section:** 9. Commercial readiness
- **Priority:** 🔴 high — was **the one commercial *blocker*** (now closed)
- **Track:** A (integrity) — research-independent; can run in parallel with §9.1
- **Independent of:** seed data and research

- **What:** Make a transaction and its per-owner shares a **single atomic write**
  with a database-level guarantee that shares reconcile to the amount.
- **How it works:** replace the current two separate writes + client-side
  compensating rollback with a transactional Supabase **RPC** (one write); add a
  `CHECK`/constraint or trigger so `sum(shares) == amount_cents`; close the
  reachable **share-less-row** path on the unhappy branch. The import CLI writes
  the same way.
- **Ortho fit:** for one household the two-write path is a rare glitch; across
  thousands of users on flaky mobile networks it's a statistical certainty that
  some ledgers half-persist and stop reconciling — and nothing at the DB level
  stops or detects it. A money product can't take payment with a ledger that can
  silently fail to reconcile. This is architectural, not cosmetic.
- **Reference:** the finance layer's own hardening backlog flags this as **H3(b)**
  (shares-sum invariant lives in convention, not in types or the DB).
