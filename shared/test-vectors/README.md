# Regression test vectors

Canonical input→output cases for the pure TS finance logic in `web/lib/*` and
`web/components/{dashboard,housing}/`. Generated by `web/scripts/gen-vectors.ts`
and asserted by the web Vitest parity suites (`web/test/*.parity.test.ts`, one
per JSON). Originally a cross-language TS↔Swift parity lock; since spec 021 the
native app is frozen and this is a **single-implementation regression/pinning
suite**. See `docs/shared.md` for the full mechanism and `PARITY.md` for the
capability contract.

## Files (13)

- `mortgage.json` — `lib/finance/mortgage.ts`: monthly payment, balance, equity,
  equity fraction, maturity, years remaining, 12-month amortization slice.
  Includes zero-interest and month-end-closing boundary cases.
- `insights.json` — `lib/finance/insights.ts` `generateInsights`: snapshot +
  pinned reference date → fired insights (`id`, `severity`, `category`,
  `magnitude_cents`, `preview_merchants`).
- `transaction-filters.json` — `lib/transactionFilters.ts` `filterTransactions`
  (`{ cases }` → `expectedIds`, order-preserved): query, categories, kind,
  sources, owners, **tags** (spec 027), half-open `dateFrom`/`dateTo`;
  OR-within / AND-across; `monthBounds('YYYY-MM')` UTC month boundary; query
  matches notes and tag names.
- `transaction-splits.json` — `lib/splits.ts`
  (`{ cases, validations, seeds, ownerOrdering }`): `computeShares`
  even/percent/value with leftover-cent placement and percent-over-tolerance
  reclaim; `validateSplit` reasons (`percent_sum`/`value_sum`/`no_owners`);
  `seedSplit` round-trips; canonical `orderedOwnerIds` over scrambled inputs.
- `currency.json` — `lib/finance/money.ts` `toDisplayAmount`/`toUSDCents` over
  all 7 currencies at fallback rates (`{ toDisplay, toUsdCents }`). Display
  *strings* are locale-dependent and deliberately NOT vectored.
- `currency-names.json` — fixed `CURRENCY_NAMES` table, keyed by code.
- `currency-symbols.json` — fixed symbol table (no locale derivation;
  `cny` = `CN¥`), keyed by code.
- `dashboard-month-scope.json` — `components/dashboard/range.ts`:
  `availableMonths`, `availableRanges`, `monthReferenceDate`, `stepMonth`.
- `member-balance.json` — `lib/balances.ts` `balanceBetween` settle-up net
  cents; expenses carry `paid_by`, reimbursements are directional `transfer` rows.
- `housing-net-rental.json` — `lib/finance/housing.ts`
  `occupiedRentCents`/`netRentalCents`. Occupancy is a resolved boolean.
- `lease.json` — `components/housing/lease.ts`: `rentDueDay`,
  `daysUntilNextRent` (incl. due-day > month-length clamp), `daysUntilEnd`,
  `isRenewalSoon`, with an injected `asOf`.
- `budget-rollover.json` — `lib/finance/budgets.ts` `computeRolloverLedger`
  (spec 027): fixed/flex/non_monthly carry recurrence, flex cap, opening carry
  (incl. negative). Contract: `specs/027-budget-rollover/contracts/rollover-math.md`.
- `goals.json` — `lib/finance/goals.ts` (spec 027): `progress` (`goalProgress`)
  and `pacing` (`goalPacing`: expected/shortfall/suggested-monthly, off-track,
  past-due), with an injected `now`.

All money is integer USD cents. Dates are timezone-stable: mortgage/lease/goal
date-only values parse as **local** calendar dates; insight transaction dates
mirror JS `new Date('YYYY-MM-DD')` (UTC midnight) and sit mid-month; filter
dates and `monthBounds` windows are **UTC** half-open `[from, to)`. The
generator pins `TZ=UTC` before any Date math.

## Regenerating

```bash
cd web && npm run gen:vectors   # writes ../shared/test-vectors/*.json
```

Never hand-edit these files — the generator reverts edits. Regenerate only on
*intended* behavior change, and review the JSON diff as a behavior-change diff:
the expected values come from the same TS engines the tests assert, so
regenerating after an unintended change silently launders the bug. CI
(`.github/workflows/web-ci.yml`) regenerates and fails on any uncommitted drift.

## Running the suite

`cd web && npm test` (Vitest — 13 `test/*.parity.test.ts`, one per JSON;
`transaction-splits.json` ↔ `splits.parity.test.ts`). Adding a new vector file
needs only a `gen-vectors.ts` section plus one parity test — the frozen iOS
app's XCTest suites are historical and no longer consume these files.

## Contract

The insight `id` scheme is part of the contract (e.g.
`top-category-dining-2026-06`, `budget-over-dining-2026-06`,
`outlier-<lowercase-uuid>`). A different id is a real behavior change, not a
test bug.
