### Why a CLI is feasible (verified this session)
- **pdf-lib generates AND unpdf reads attachments in Node headlessly** — confirmed by a
  live spike and by `web/test/dataFile/*` (node-env Vitest). No browser needed.
- The section serialize/read/dedupe are pure. Amounts are canonical USD cents; display
  currency is render-only (import ignores `display`).

### What the CLI needs to add (the actual work)
1. **Read-only `DataStore` adapter for export** — authenticate + load the household's
   transactions (with `transaction_shares`), properties (+ mortgage/lease/units), rental
   payments, people, tags. Pattern already exists in `scripts/import/db/` (`client.ts`
   `loadEnv`/`makeClient`, `lookups.ts` `resolveHousehold`) AND is demonstrated in the
   throwaway `web/scripts/_diag.ts` (loads tx + paginated shares — NOTE the 1000-row
   PostgREST cap: paginate transactions AND `transaction_shares` with `.range()`).
2. **A Node `RenderCtx`** — provide `t` (identity or a loaded catalog), `locale`,
   `formatMoney` (use `pdf/money.ts` `formatMoneyForPdf`), `resolveUser`, `rate`.
   Then `buildDataFile(store, {language, currency, now, includeSections}, t, rate)` →
   write bytes to disk.
3. **Supabase-writing `DataStore` adapter for import** — implement `addTransaction`
   (route through the atomic `upsert_transaction` RPC like the web store / `scripts/import/db/persist.ts`),
   `addProperty` (+ subtables), `addRentalPayment`, `addTag`. Then
   `readEnvelope` → `planImport` → show plan → `applyImport(plans, store, {now})`.
   Import is additive + idempotent (tier-1 canonical id, tier-2 CSV fuzzy matcher).
4. **Makefile targets** mirroring `make ingest`'s auth (OTP via `IMPORT_EMAIL`, or
   `ADMIN=1` + `SUPABASE_SERVICE_ROLE_KEY`), `DRY_RUN=1`, `YES=1`. Suggest:
   `make data-export FILE=out.pdf [LANG=..] [CURRENCY=..] [ADMIN=1]` and
   `make data-import FILE=in.pdf [DRY_RUN=1] [YES=1] [ADMIN=1]`.
5. **Tests + a short doc** (extend `docs/makefile.md`). Keep `npm test` + `tsc` green.
