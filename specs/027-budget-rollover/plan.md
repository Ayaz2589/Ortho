# Implementation Plan: Budget rollover & bucket types

**Branch**: `feat/budget-rollover` | **Date**: 2026-07-18 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/027-budget-rollover/spec.md`

## Summary

Extend the existing `budgets` table (one `monthly_limit_cents` per household +
category) with a **type** (`fixed` | `flex` | `non_monthly`) and an optional
**rollover cap**, and add a pure, golden-vector-locked rollover engine that
carries an unused remainder from one month into the next. The dashboard budget
card and the budget-status insight rule both switch from the raw monthly limit to
the rollover-aware **effective** limit, so per-bucket *remaining* is visible and
the two surfaces never disagree. Carry is **derived** from transaction history on
every render — no stored running balance, no month-close job — keeping the model
driftless and offline-correct. `fixed` is the default, so every pre-existing
budget is byte-for-byte unchanged.

Technical approach:
- New pure engine `web/lib/finance/budgets.ts`: `computeRolloverLedger(config,
  monthlySpendCents[])` → per-month `{ carriedIn, effectiveLimit, spent,
  remaining, carriedOut }`, plus a thin `budgetStatusForMonth(...)` adapter that
  reduces a transaction ledger to the monthly-spend series and returns the
  selected month's status.
- Golden vectors `shared/test-vectors/budget-rollover.json` (generated by
  `gen-vectors.ts`, asserted by `web/test/budget-rollover.parity.test.ts`) —
  written **first** (RED), then the engine implemented to green (GREEN).
- Migration adds `budget_type` (enum, default `fixed`) + `rollover_cap_cents`
  (nullable) to `budgets`.
- Thread the two new fields through `lib/types.ts`, `lib/supabase/rows.ts`, and
  the store's budget CRUD; make `BudgetProgressCard` and insights Rule 3
  rollover-aware; add a type selector + cap field to `BudgetDrawer`; add i18n
  keys in all five catalogs.

## Technical Context

**Language/Version**: TypeScript ^5 (strict), React 19.2.4, Next.js 16.2.9 (App
Router, `output: 'export'`). Node ≥ 20.19 / ≥ 22.12.

**Primary Dependencies**: `@supabase/supabase-js`, Tailwind v4, Vitest ^4.1.8,
`tsx` (vector generation). No new dependency.

**Storage**: Supabase Postgres — `budgets` table (adds `budget_type` enum +
`rollover_cap_cents bigint null`). All money is integer USD cents.

**Testing**: Vitest (`npm test`); golden-vector regression suite
(`web/test/*.parity.test.ts` ↔ `shared/test-vectors/*.json` via
`npm run gen:vectors`); jsdom component tests for the card/drawer.

**Target Platform**: Responsive web + the Capacitor iOS shell (same bundle). No
iOS-native code; the sandbox is Linux (no Xcode) — iOS is CI-verified.

**Project Type**: Web (single canonical implementation).

**Performance Goals**: Carry computation is O(budgeted categories × months since
anchor) over the already-in-memory ledger; memoized in the card exactly like
today's single-pass spend aggregation. No network round-trips added.

**Constraints**: Integer-cents, no rounding drift; local-calendar month
bucketing (never raw `new Date('YYYY-MM-DD')` for boundaries); vitest pins
`TZ=UTC`; offline-correct (carry derived, not fetched).

**Scale/Scope**: One new pure engine file (~1 vectored function + 1 adapter), one
migration, one new vector file + parity test, edits to ~7 existing files
(types/rows/store/card/insights/drawer/i18n).

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **I. One Design System, Tokens Only** — PASS. The card adds a "remaining" figure
  and a rolled-over caption using existing tokens (`--text`, `--text-3`,
  `--positive`, `--accent`, `--chip-bg`). No new colors. The type selector reuses
  the existing segmented-control / choice-row patterns.
- **II. Calm Over Dense** — PASS. One extra line of secondary text per bucket
  (remaining + optional "＋$X rolled over"); no new density, no shadows, no
  gradients. Loss/over-budget is conveyed by bar fullness and position, never red
  (FR-013).
- **III. Right Form Factor Per Canvas** — PASS. Card renders in both the mobile
  stack and `DashboardDesktop`; the drawer is the existing mobile/desktop
  `BudgetDrawer`. No new layout surface.
- **IV. Plainspoken Voice & Money Formatting** — PASS. Copy is second-person and
  plain ("Fixed / Flex / Non-monthly", "$100 rolled over"). Amounts use
  `formatMoney` (tabular, Unicode minus, never abbreviated).
- **V. Accessible & Interaction-Complete** — PASS. Type selector is real
  `<button>`/radio semantics, keyboard-reachable, sand focus ring; cap input is a
  labelled money input. Progress bars are decorative with text equivalents.
- **VI. Test-Driven & Regression-Safe (NON-NEGOTIABLE)** — PASS and central. The
  rollover math is pure and gets golden vectors **written first**; the engine is
  implemented to satisfy them. Insights stay byte-identical for `fixed` (default),
  so existing `insights.json` does not move except for deliberately-added
  flex/non_monthly cases. Reference dates are injected, never the real clock.

## Phasing (TDD, per constitution Principle VI)

1. **RED — vectors + failing tests.** Author the rollover recurrence contract,
   add the `budget-rollover` section to `gen-vectors.ts`, write
   `budget-rollover.parity.test.ts` and the engine unit tests. They fail because
   `web/lib/finance/budgets.ts` does not yet export the functions.
2. **GREEN — engine.** Implement `computeRolloverLedger` + `budgetStatusForMonth`
   to satisfy the vectors; `npm run gen:vectors` writes the JSON; suite goes
   green.
3. **Schema.** Add the migration; `supabase db reset` to replay locally.
4. **Wire data layer (test-first per unit).** Extend `Budget`/`BudgetRow` types,
   store upsert, seed; make card + insights rollover-aware (new insight vectors
   for flex/non_monthly; fixed stays identical); add the drawer type selector +
   cap and i18n keys.
5. **Verify + reconcile.** `npx tsc --noEmit`, `npm test` green, vector-drift
   clean; update `PARITY.md` (new matrix row) and docs (`docs/web.md`,
   `docs/shared.md`, `docs/index.md`, `docs/supabase.md`). Commit, push, PR.
