# Implementation Plan: Income Deposit Accounts

**Branch**: `feat/income-deposit-accounts` | **Date**: 2026-07-30 | **Spec**: [spec.md](./spec.md)

## Summary

Replace the hardcoded `INCOME_SOURCES` constant in `TxForm.tsx` with a user-configurable `deposit_accounts` table (mirrors `cards`). Users manage deposit account names in Settings → Deposit Accounts; the income "Deposit to" picker shows their accounts. No changes to `transactions` — `source` already stores the name string. Fully additive; expense flow untouched.

## Technical Context

**Language/Version**: TypeScript 5.x / React 18
**Primary Dependencies**: Next.js App Router, Supabase JS client, Tailwind v4
**Storage**: PostgreSQL via Supabase — new `deposit_accounts` table (mirrors `cards`)
**Testing**: Jest + React Testing Library (`npm test` from `web/`)
**Target Platform**: Web (responsive: compact/medium/expanded); iOS via Capacitor shell
**Project Type**: Web application (Next.js)
**Performance Goals**: Additive read (one extra SELECT in `loadAll` fan-out) — negligible
**Constraints**: Fail-open on missing table during deploy-before-migrate window
**Scale/Scope**: Household-scoped list; expected < 10 entries per household
