# Data Model: Cross-Platform Parity Remediation

**No schema migrations.** All tables already exist. This documents the data *representations* and *state
transitions* the two clients must agree on. The shared golden vectors lock the pure transforms.

## Entities

### Session / Auth phase (client-side state machine — NEW on iOS)

The signed-in context, derived from the SDK's persisted session.

| Phase | Meaning | Renders |
|---|---|---|
| `launching` | App started; session restore in progress (synchronous read + optional refresh) | Neutral launch/splash |
| `signedIn` | Valid (or just-refreshed) session present | `RootTabView` + bootstrap → data |
| `signedOut` | No session, or refresh failed | `SignInView` |

**Transitions**:
- launch → read `currentSession`: present & not expired → `signedIn`; present & expired → attempt
  `refreshSession()` → success `signedIn`, failure `signedOut`; absent → `signedOut`.
- `signedIn` → sign-out → tear down all domain state, reset `bootstrappedAuthID` → `signedOut`.
- token expiry while running → refresh (not drop) → stay `signedIn`; only `signedOut` on refresh failure.

iOS currently lacks `launching`; the gate is `session != nil` with `session` set only asynchronously. Web's
equivalent is the server `getUser()` gate in middleware/proxy (already correct).

### Transaction owner share (representation contract)

Authoritative per-owner allocation. **Stored** as `transaction_shares(transaction_id, person_id,
amount_cents)`. Invariants both clients MUST honor:

- `sum(amount_cents over owners) == transaction.amount_cents` exactly.
- Derived from a `SplitInput`: `even` | `percent[]` | `value[]` via the shared `computeShares(amountCents,
  orderedOwners, splitInput)`; leftover cent placed deterministically (floor + distribute in owner order).
- **Kind-agnostic**: income and expense split identically (R6).
- **Edit round-trip**: reopening a stored split MUST reproduce a `SplitInput` that re-emits the SAME cents.
  A non-even stored split reopens as `value` seeded from exact stored cents (R7); an even split reopens as
  `even`. "Non-even" = stored shares ≠ `computeShares(amount, owners, .even)`.

### Household person

`household_people(id, household_id, name, initial, color_key, linked_user_id, sort_order, removed_at)`.

- **Editable after creation** (the gap): `name` and `color_key` are mutable on both clients via a targeted
  `updatePerson` (optimistic local update + rollback on failure).
- The account holder is the person with `linked_user_id == auth.uid()`; it is editable (name/color) but not
  removable.
- Active = `removed_at IS NULL`; pickers/lists show active only (already true on both).

### Insight (ID contract)

Generated spending observation. The **stable ID** is a cross-client de-dup/snooze key and a vector contract.

- IDs are input-deterministic and identical across clients, following the web scheme documented in
  `shared/test-vectors/README.md` (e.g. `cashflow-deficit`, `cashflow-savings`, …). No period-key suffix.
- Every rule that can fire is represented in `insights.json` so both suites assert its ID + payload.

### Active-platform lock

`platform_locks(user_id, platform, locked_at)` — already exists; web reads/writes it, iOS must too (R5).

- One active platform per user. iOS upserts `platform='ios'` at bootstrap, deletes on sign-out, and yields
  (calm "active on another device" state) when an active `web` lock is present — symmetric with web.

### Golden vector (the contract artifact)

`shared/test-vectors/{transaction-splits,insights,mortgage,transaction-filters}.json` — input/expected pairs
generated by `web/scripts/gen-vectors.ts`, asserted by **both** Vitest and (after R9) XCTest.

- Changed: `transaction-splits.json` += income-split + custom-split edit-prefill cases.
- Changed: `insights.json` regenerated to cover all rules with canonical IDs.

## Validation rules (from FRs)

- FR-001..003: auth phase resolves before the gate renders; never flash `SignInView` for a valid session.
- FR-004: sign-out clears every domain collection + `currentHouseholdID` + `bootstrappedAuthID`.
- FR-005: one OTP length constant per client == production length; copy matches.
- FR-008/010: income splits persisted; per-owner cents sum to total; identical across clients.
- FR-009: custom split edit/copy round-trips to the cent.
- FR-011: person name + color editable, persisted, cross-client visible.
- FR-014: insight IDs match the single contract; all rules vectored.
- FR-015/016: desktop detail shows per-owner cents+percent; desktop dashboard shows category + per-member.
- FR-017: web `locale` driven by language selection; persists.
