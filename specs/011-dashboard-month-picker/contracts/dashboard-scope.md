# Contract: Dashboard scope + month picker

Mirrored pure functions (TS ↔ Swift), the new golden-vector schema, and the UI control contract. Names are illustrative; match each surface's existing conventions.

## 1. Shared pure functions (mirrored, lockstep)

### `availableMonths(transactions) → 'YYYY-MM'[]`  — **VECTORED**

- Month key = first 7 chars of the transaction's stored ISO `date`.
- Returns distinct keys sorted **descending** (newest first). Empty in → empty out.
- web: `components/dashboard/range.ts`; iOS: `DashboardRange.swift`. Asserted by both suites against `dashboard-month-scope.json`.

### `monthScopeInterval(scope, now) → Interval`

- `scope = { range, selectedMonth }`.
- `selectedMonth != null` → `monthBounds(selectedMonth)` (existing, vectored).
- else → `rangeInterval(range, now)` (existing).
- Half-open `[from, to)`. Thin resolver; covered by per-surface unit tests (relies on already-vectored pieces).

### `monthReferenceDate('YYYY-MM') → Date`

- The **15th at 12:00 UTC** of that month. Used as the reference date for Budget/Insights when a month is selected so both platforms' calendar math lands on the selected month (see research D3).
- Unit-tested per surface (deterministic).

### `stepMonth(months, current, direction) → 'YYYY-MM' | null`

- `months` = `availableMonths(...)` (desc). `direction ∈ {prev, next}`.
- Returns the adjacent key, or `null` at an edge (earliest for `prev`, latest for `next`).
- `canStepPrev`/`canStepNext` derive from a non-null result. Unit-tested per surface.

## 2. Golden vector schema — `shared/test-vectors/dashboard-month-scope.json`

Generated by `web/scripts/gen-vectors.ts`; asserted by web Vitest **and** iOS XCTest.

```jsonc
{
  "availableMonths": [
    {
      "name": "string — case description",
      "dates": ["2026-06-15T12:00:00.000Z", "2026-05-02", "2026-06-30T23:59:59.000Z", "..."],
      "expected": ["2026-06", "2026-05", "..."]   // distinct keys, newest-first
    }
    // cases: empty; single month; multiple months unsorted; duplicate-day same month;
    // boundary timestamps (month-end 23:59:59Z and month-start 00:00:00Z must key by the
    // STRING slice, not a local Calendar re-bucket); a year boundary (Dec→Jan).
  ]
}
```

- Each test feeds `dates` (just the `date` field matters) → asserts `availableMonths === expected`.
- **No change** to existing vector files; `transaction-filters.json` continues to lock `monthBounds`.

## 3. UI control contract — `MonthPicker` (both surfaces)

A stepper with a tap-to-open month list, placed **beside** the existing relative range picker in the dashboard header.

**Inputs/props:**

- `availableMonths: 'YYYY-MM'[]` (desc), `selectedMonth: 'YYYY-MM' | null`.
- `onSelectMonth('YYYY-MM')`, `onClear()` (back to relative/"Latest").

**Behavior:**

- Renders `‹ June 2026 ›` when a month is selected; tapping the label opens the newest-first month list (reuse the Transactions filter month-list pattern) to jump.
- When no month is selected, the control shows an entry affordance (e.g. the latest month label or a "Pick a month" control) consistent with the surface; choosing a relative range keeps `selectedMonth = null`.
- `‹` disabled when `selectedMonth` is the earliest available month; `›` disabled at the latest. Disabled uses `--text-3`, not a new color.
- Provides a visible way back to the relative view ("Latest"), which calls `onClear()`.
- Month labels: `"June 2026"` (existing month-label formatter; respects locale).

**Accessibility (Constitution V):**

- Real `<button>` (web) / `Button` (iOS); month list items are real options.
- Prev/next carry accessible labels ("Previous month" / "Next month") and correct `disabled` state at edges.
- Hit targets ≥40px (≥44 touch); visible sand `:focus-visible` ring on web; keyboard reachable in DOM order; `prefers-reduced-motion` honored for any list/menu transition.

**Design (Constitution I/II):**

- Tokens only; matches the weight/spacing of the existing `Seg`/`RangePicker`. No shadow on the inline control (the popover/menu may float, using existing menu chrome). No new palette entries.

## 4. Card wiring contract

- **Interval-driven (no logic change, receive `activeInterval`):** MonthSummary, SpendByCategory, PerOwnerBreakdown, TopMerchants.
- **Rewired to `referenceDate`:** BudgetProgress (use `monthBounds(selectedMonth)` when set, else current month), Insights (pass `referenceDate` into `generateInsights`/`InsightEngine`).
- **Untouched (period-independent by design):** DailySpendTrend (trailing-30), HousingSnapshot (point-in-time).
