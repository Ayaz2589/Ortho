# 9.1 Seed-data harness + edge-case coverage corpus

- **Section:** 9. Commercial readiness
- **Priority:** 🔴 high — **Feature 1 (spec next)**
- **Track:** A (integrity) — research-independent, unblocked, do first
- **Doubles as:** the verification harness for §9.4 (reproduces the timezone
  and CLI-split bugs)

- **What:** A deterministic seed-data generator plus a library of deliberately
  diverse **edge-case scenarios** that exercise the whole finance model — not
  polished demo data (that's §9.2), but a coverage corpus.
- **How it works:** a pure generator emitting households / members / transactions
  / properties / budgets across a coverage matrix: multiple households (joint +
  separate), all split types (even / percent / value), multi-currency (USD, EUR,
  JPY, BDT), **non-UTC timezones**, **month-boundary dates** (1st / last-of-month),
  refunds & negatives, sparse vs dense months, properties / mortgages / leases
  (incl. paid-off), budgets across the under/near/over bands, recurring merchants.
  Runnable to seed a dev/demo DB and consumable as a test corpus.
- **Ortho fit:** the connective-tissue artifact — it feeds testing, demo, and
  design validation at once. Two of its scenarios (non-UTC boundary dates;
  `sort_order` ≠ lexical-id households) are exactly what's needed to verify the
  §9.4 bugs, so building it and verifying those bugs is one activity.
- **Scope note:** **coverage over volume.** A few hundred deliberately varied
  households catch bugs and validate design; a large pool of near-identical clones
  only tests scale (a later performance concern).

> Source: the commercial-readiness & sequencing review (2026-07-17).
