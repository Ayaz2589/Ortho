## Completeness critic — what the sweep may have under-checked

_Audit holds; it under-examined off-screen data divergences. Top 3 below._

- **Transaction-and-shares two-table write partial-failure divergence** — Web writeShares at store.tsx line 473 runs fire-and-forget after the parent insert with no error capture, so a shares failure leaves a share-less parent rehydrating as creator-owns-all; iOS commits both as one throwing unit with rollback at TransactionsAPI.swift line 51.  
  _Next check:_ Add catch and rollback to web writeShares or a create_transaction_with_shares RPC; force a shares-insert RLS denial and confirm both clients match.
- **Owner ordering: iOS uuidString sort vs web array order moves the leftover cent** — iOS sorts the ownerIDs Set by uuidString at Transaction.swift line 55 but web keeps insertion order at splits.ts line 53, so the leftover cent lands on a different owner; the vector passes a pre-ordered array at TransactionSplitParityTests.swift line 77 and never exercises the Set path.  
  _Next check:_ Fixture with two or more owners whose array order differs from uuidString order at an odd amount; compare effectiveShares iOS vs web; canonicalize owner order or vector the Set-shaped input.
- **Currency conversion toUSDCents and displayAmount have zero vector coverage** — Web money.ts uses float and Math.round, iOS Money.swift uses Decimal and NSDecimalRound plain; they round halves oppositely, so the same foreign amount can store different USD cents per client despite identical FX rates, a silent ledger divergence with no vector.  
  _Next check:_ Add a shared toUSDCents and toDisplayAmount vector across all seven currencies, asserted from both suites; first diff Math.round vs NSDecimalRound plain.
