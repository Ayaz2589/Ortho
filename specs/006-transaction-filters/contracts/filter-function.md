# Contract: `filterTransactions` (TS + Swift, vector-locked)

The single behavioral contract both clients implement identically (FR-013/14, SC-002).

## Signature
- **TS** (`web/lib/transactionFilters.ts`):
  `export function filterTransactions(txs: Transaction[], c: FilterCriteria, ctx: FilterContext): Transaction[]`
- **Swift** (`TransactionFilters.swift`):
  `func filterTransactions(_ txs: [Transaction], _ c: FilterCriteria, _ ctx: FilterContext) -> [Transaction]`

## Rules (see data-model.md for the per-dimension predicate)
1. Pure: no IO, no clock, no store. Output order = input order (input is newest-first).
2. AND across the 7 dimensions; OR within a multi-select; empty/`all`/null = no constraint.
3. Search compares the lowercased, trimmed `query` as a substring of `merchant`, `source`, `category`, and each owner's `ctx.ownerNames[id]`.
4. Date window is half-open `[dateFrom, dateTo)`, compared as instants.
5. Selected-but-absent values (a source/owner no longer present) simply match nothing — never throw.

## Parity test (both suites)
For every case in `shared/test-vectors/transaction-filters.json`:
```
filterTransactions(case.transactions, case.criteria, case.context).map(t => t.id) === case.expectedIds
```
- **Web**: `web/test/transaction-filters.parity.test.ts` (Vitest, node env) loads the JSON and asserts each case.
- **iOS**: `TransactionFilterParityTests.swift` (XCTest) decodes the bundled JSON and asserts each case.
- Vectors are generated by `web/scripts/gen-vectors.ts` from the TS implementation (source of truth) — regenerate only when intended behavior changes, then run **both** suites.

## Vector coverage (cases the generator must emit)
- Each dimension alone: scope (shared/personal), search (merchant/source/category/owner-name hit + miss), category (single + multi OR), kind (expense/income), source (single + multi OR), owner (single + multi OR), date (from only, to only, month window incl. boundary day).
- Combinations: scope∧category, kind∧source, owner∧month, search∧category (AND across dims).
- Edge: empty result (no match), `emptyCriteria` returns all input, selected-but-absent source/owner → empty, month-boundary transaction lands in the right month.

## `activeFilterCount` / `availableSources` / `monthBounds`
Also mirrored and unit-tested per platform (web `transaction-filters.test.ts`), but `filterTransactions` is the vector-locked contract. `monthBounds('2026-05') → { dateFrom: <May 1 00:00>, dateTo: <Jun 1 00:00> }` (timezone-stable ISO).
