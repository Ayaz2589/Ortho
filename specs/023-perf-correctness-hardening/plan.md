# Implementation Plan: Web + iOS Performance & Correctness Hardening

**Branch**: `023-perf-correctness-hardening` | **Date**: 2026-07-14 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/023-perf-correctness-hardening/spec.md` + audit dossier [audit-findings.md](./audit-findings.md) (exact `file:line` fix directions — the implementation source of truth).

## Summary

Land the fixes from a four-part codebase audit under one guarantee: **faster and more correct, with no change to what is computed or how it looks.** Three kinds of change, sequenced by priority:

1. **Correctness bug fixes** (behavior changes, each test-first): the HIGH FX-split-shares corruption in non-USD currencies (B1), month-scoped budget insights (B2), the iOS scan camera dismissal + multi-page capture (B3), the biometric-lock full-reload (B4), foreground `getUser` liveness (B5), the stale "6-digit" copy (B6), unchecked rollback writes (B7), the web text-selection leak (B8), and the iOS status-bar/re-entrancy tail (B9).
2. **Performance wins** (behavior- and pixel-identical): lazy-load i18n catalogs (P1), memoize `Intl` formatters (P2) and dashboard aggregations (P3), split + memoize the store context and `React.memo` rows (P4), and column-project `loadAll` (P5).
3. **Maintainability/type-safety** (no user-facing change): type the Supabase→domain boundary (typegen or a typed mapper), a `Transaction` transfer accessor, dedup (`useMonthAccordion`, `<TxFormBody>`), dead-code purge (dead i18n keys + reintroduction guard, `relativeTime`), and resolving the unwired `aggregates.ts`.

**Technical approach**: pure-TS and React-render changes only — no schema migration, no server surface. Every perf/refactor item is validated against the finance regression-vector suites + the full Vitest suite + `tsc --noEmit` staying green (byte-identical output); every bug fix begins with a failing test that reproduces the defect (Principle VI). iOS Swift/native-lifecycle changes are build-verified by the Capacitor iOS CI on push (a Linux sandbox cannot build iOS). Static export (`output: 'export'`) is preserved by construction: any new dynamic import uses `{ ssr: false }`; no route handlers, `cookies()`/`headers()`, server actions, or middleware are introduced.

## Technical Context

**Language/Version**: TypeScript 5 (strict, `@/*` alias) · React 19.2 · Next.js 16.2 (App Router, `output: 'export'`, Turbopack) · Swift (Capacitor iOS shell + custom Scan plugin).

**Primary Dependencies**: `@supabase/supabase-js` ^2.108 + `@supabase/ssr` ^0.12 · Tailwind v4 · `lucide-react` · `recharts` (already code-split, spec 022) · Capacitor 8 plugins (`@capacitor/app|status-bar|splash-screen|haptics|share`, `@aparajita/capacitor-biometric-auth|secure-storage`, `@capawesome/capacitor-file-picker`).

**Storage**: Supabase Postgres (RLS; USD-cents `bigint`) · `localStorage` (prefs, FX cache, flags) · iOS Keychain (session, spec 021). **No schema change in this feature.**

**Testing**: Vitest 4 (node + jsdom via `// @vitest-environment jsdom`) + Testing Library · regression fixtures in `shared/test-vectors/*.json` (asserted by `*.parity.test.ts`, regenerated by `npm run gen:vectors`) · bundle measurement via `npm run measure:bundle` (spec 022) · Capacitor iOS build CI (`.github/workflows/capacitor-ios-ci.yml`, macOS runner). Web CI: `.github/workflows/web-ci.yml` runs `tsc`, `npm test`, vector-drift on Linux.

**Target Platform**: modern browsers (desktop + mobile) and iOS (Capacitor WKWebView), served from one static export.

**Project Type**: single canonical web/TypeScript implementation (`web/`) delivered to two targets; a Capacitor iOS shell (`web/ios/App/`) wraps the same bundle.

**Performance Goals**: initial-load JS below the spec-022 baseline (i18n catalogs, ~30 KB gzip, leave initial load; default-language users fetch none) · eliminate per-row `Intl` formatter reconstruction and whole-list re-renders on unrelated state changes · no FPS/interaction regression · no change to any displayed value.

**Constraints**: static-export-only (no server/SSR/route handler/middleware; dynamic imports `ssr:false`) · integer USD cents everywhere · design tokens only (no new color/token; the one copy change is the B6 "8-digit" correction) · perf/refactor items behavior- and pixel-identical (vectors + tests + `tsc` green) · iOS runtime behaviors verified via CI/manual device check, not locally.

**Scale/Scope**: 25 functional requirements across 7 prioritized user stories. Touch set: `lib/i18n/*`, `lib/store.tsx`, `lib/finance/{money,format}`, `lib/types.ts`, `lib/supabase/client.ts`, `components/web/{TxForm,TxModalWeb}.tsx`, `components/dashboard/{InsightsCardStack,MonthSummaryCard,BudgetProgressCard}.tsx`, `components/dashboard/range.ts` + `lib/finance/insights.ts`, `app/(app)/transactions/page.tsx`, `app/(app)/layout.tsx`, `app/globals.css`, `lib/biometricGate.ts`, and Swift under `web/ios/App/App/Plugins/Scan/` + `components/settings/appearance.ts`.
