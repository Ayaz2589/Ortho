# Phase 1 Data Model

No database schema changes. This documents the affected logical entities and the **new/extended golden
vector shapes** both clients assert.

## Entities (unchanged schema; behavior reconciled)

- **Owner share allocation** — per-owner cents that sum to the transaction total. Computed from an even /
  percent / value split. The leftover cent (even/percent) is placed on the first owner in the **canonical
  order** = owner-id strings sorted ascending (R1). Stored explicitly in `transaction_shares`; the canonical
  order matters only when shares are *computed* (creation / even-fallback), not when read back.
- **Currency conversion** — pure transforms between stored USD cents and a display currency at rate
  `r` (1 USD = r units): `toDisplayAmount(cents,cur,r) = round((cents/100)*r, fractionDigits(cur))`,
  `toUSDCents(amount,cur,r) = round((amount/r)*100)`, both round **half away from zero** (R2). Currencies +
  fraction digits: usd/cad/gbp/eur/cny/bdt = 2, jpy = 0.
- **Transaction + shares write** — the parent `transactions` row and its `transaction_shares` rows form one
  logical unit; a partial failure must leave neither (client-side rollback, R3).
- **Insight (recurring, outlier)** — recurring `magnitude_cents` uses truncated integer average (R6);
  outlier id = `outlier-<lowercase-uuid>` on both clients (R8).
- **Mortgage schedule** — current balance/equity derive from months-elapsed, counted with Calendar-style
  month-end clamping (R7).

## New / extended vector shapes

All under `shared/test-vectors/`, generated by `web/scripts/gen-vectors.ts`.

### `transaction-splits.json` → add `ownerOrdering` (R1)

```jsonc
{
  "cases":       [ /* unchanged */ ],
  "validations": [ /* unchanged */ ],
  "seeds":       [ /* unchanged */ ],
  "ownerOrdering": [
    {
      "name": "even-three-remainder-2-scrambled",
      "amountCents": 10001,
      "owners": ["c","a","b"],          // scrambled input
      "ordered": ["a","b","c"],          // orderedOwnerIds(owners)
      "split": { "method": "even" },
      "expected": { "a": 3334, "b": 3334, "c": 3333 }  // computeShares(amount, ordered, split)
    }
    // + cases with UUID-form ids in non-sorted order, percent leftover, single owner
  ]
}
```

Assertion (both suites): `computeShares(amountCents, orderedOwnerIds(owners), split) == expected`
**and** `orderedOwnerIds(owners) == ordered`.

### `currency.json` (NEW, R2/R5)

```jsonc
{
  "toDisplay": [
    { "name": "usd-8742", "cents": 8742, "currency": "usd", "rate": 1,    "expected": 87.42 },
    { "name": "gbp-8742", "cents": 8742, "currency": "gbp", "rate": 0.78, "expected": 68.19 },
    { "name": "jpy-575",  "cents": 575,  "currency": "jpy", "rate": 150,  "expected": 863 },
    /* … all 7 currencies at fallback rates + a couple of clean half-cent ties … */
  ],
  "toUsdCents": [
    { "name": "usd-87.42", "amount": 87.42, "currency": "usd", "rate": 1,    "expected": 8742 },
    { "name": "jpy-863",   "amount": 863,   "currency": "jpy", "rate": 150,  "expected": 575 },
    /* … */
  ]
}
```

`expected` numbers are generated from the TS implementation; iOS asserts equality (Decimal → Double for
comparison, exact integer for `toUsdCents`). **Display strings are NOT vectored** (locale-dependent).

### `mortgage.json` → add day-29–31 boundary inputs (R7)

Append `MORTGAGE_INPUTS` rows: closing `2026-01-31`, viewed at `2026-02-27`, `2026-02-28`, `2026-03-01`,
`2026-03-31` (and a 30yr loan so balance/equity differ measurably). Existing `expected` shape unchanged;
the values exercise the corrected `monthsElapsed`.

### `insights.json` → add the outlier scenario (R8)

A new `InsightScenario` with lowercase-UUID tx ids: ≥5 trailing same-category expenses (e.g. dining
1000/1100/1200/1300/1400 across prior months) + a current-month dining expense ≥2× the median (e.g. 3000),
plus income ≥ expenses to keep other rules deterministic. The generated `expected` list includes
`{ id: "outlier-<uuid>", severity, category: "dining", magnitude_cents: 3000 }`.

The recurring scenario's `magnitude_cents` is regenerated under the truncated average (R6); the value may
change from the current file — that is the intended behavior change, asserted identically by both suites.
