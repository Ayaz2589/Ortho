# Data Model: Drift Reconciliation

This feature is mostly behavior/prose reconciliation; the only persistent-data change is the occupancy column. It also introduces new golden-vector shapes and formalizes the i18n catalog invariant.

## 1. Schema change — `units.occupied`

**Table**: `units` (multifamily rental units; child of `properties`).

**New column**:
| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `occupied` | `boolean` | NOT NULL | `true` | Explicit occupancy; replaces tenant-name inference for net rental income. |

**Backfill (same migration, before/at NOT NULL)**:
```
occupied := (tenant_name IS NOT NULL AND btrim(tenant_name) <> '')
```
so every existing unit's `occupied` equals its current *inferred* occupancy → no displayed net changes.

**RLS**: none new — `units` already inherits household-member RLS; `occupied` is an ordinary column on an existing policy surface.

**Client mirrors**:
- web `web/lib/types.ts` `Unit` → add `occupied: boolean`.
- iOS `Models/Unit.swift` → add `occupied: Bool` with snake_case `CodingKey` `occupied`; keep the lenient/`isVacant` helpers but source occupancy from the column.

**Consumption**:
- `web/lib/finance/housing.ts` `rentUnitsFrom(units)` maps `occupied: u.occupied` (was `isUnitOccupied(u.tenant_name)`).
- iOS `HousingMath` / `Property.occupiedMonthlyRentCents` reads `unit.occupied`.
- The pure `occupiedRentCents`/`netRentalCents` are **unchanged** (they already take `{ rentCents, occupied }`), so `shared/test-vectors/housing-net-rental.json` stays byte-identical.

**State**: `occupied` is user-settable via the add/edit unit editor on both apps; new units default to occupied (`true`) and the editor exposes an explicit toggle.

## 2. New golden-vector shapes

Generated by `web/scripts/gen-vectors.ts`, asserted by a web `*.parity.test.ts` + an iOS `*ParityTests.swift`, wired into `project.pbxproj`.

### `currency-names.json`
```jsonc
{ "usd": "US Dollar", "cad": "Canadian Dollar", "gbp": "UK Pound",
  "eur": "Euro", "jpy": "Japanese Yen", "cny": "Chinese Yuan", "bdt": "Bangladeshi Taka" }
```
Pins `CURRENCY_NAMES` (TS) == `Currency.displayName` (Swift) for all 7. (Exact non-GBP names captured from the current iOS enum during implementation; GBP canonicalized to "UK Pound".)

### `currency-symbols.json`
```jsonc
{ "usd": "$", "cad": "$", "gbp": "£", "eur": "€", "jpy": "¥", "cny": "CN¥", "bdt": "৳" }
```
A **fixed canonical symbol table** (no locale derivation) hardcoded on both platforms. Exact glyphs are captured from the current iOS en-US rendering during implementation; `cny` is canonicalized to `CN¥` (disambiguated from `jpy ¥`).

### `lease.json`
Array of `{ input, expected }` with a pinned `asOf` (and `TZ=UTC` in generation, `TZ=America/New_York` in the TZ-sensitive web test) covering `rentDueDay`, `daysUntilNextRent` (incl. **due-day > month length clamp** and the "Due today" = 0 case), `daysUntilEnd`, and `isRenewalSoon`. Mirrors `web/components/housing/lease.ts` ↔ iOS `Models/LeaseInfo.swift`. This is the first vector for lease math (none existed).

### `transaction-filters.json` (intentional additions)
New cases added to the existing file (regenerated): a query with a trailing newline (trims to non-active), and a mixed-case `availableSources` set asserting localized case-insensitive order. Existing cases unchanged.

## 3. i18n catalog partition (invariant, not data)

Each `web/lib/i18n/{bn,es,ja,zh,ko}.ts` is a two-region map split by the `— web-only keys —` marker:
- **Above the marker (shared block)**: keys that also exist in iOS `Localizable.xcstrings`.
- **Below the marker (web-only block)**: keys with NO iOS counterpart.

**Invariant to enforce (new)**: the below-marker key set is **disjoint** from the iOS xcstrings key set. `web/test/i18n/catalog-parity.test.ts` gains an assertion for this; today it only checks shared ⊆ xcstrings, missing ~34 mislabeled keys. All five catalogs must carry the same shared-key set (fixes `es.ts`).

## 4. Reference entities (no storage)

- **Drift item** — one row of `drift-inventory.md` (surface, kind, file:line, claim, reality, fix, severity); the unit of work, tracked to closure.
- **Parity contract** — `PARITY.md` matrix rows reconciled where a fix changes a capability (esp. CLI `paid_by`).
